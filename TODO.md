## 🤖 Капстоун-фича: "Рецепты из списка" (Laravel AI SDK)
- [ ] Собрать купленные товары юзера → Laravel AI SDK (`laravel/ai`) → предложить рецепты. Связывает всё: Eloquent + контроллер + внешний AI API + структурированный вывод + тесты через fakes.
- [ ] Кэш рецептов в БД (таблица `recipes`, ключ = нормализованный набор ингредиентов): не переспрашивать ИИ на тот же набор — быстрее, дешевле, работает даже при лимите. Это и оптимизация, и fallback №1.
- [ ] Поиск похожего набора в кэше (нечёткий матч) → отдать близкий сохранённый рецепт.
- [ ] Агент с инструментами (tool-calling; AI SDK умеет agents+tools): LLM сам решает — придумать рецепт ИЛИ вызвать рецептный API (напр. стандартное блюдо → lookup, необычное → генерит). Тогда Recipe API — не только fallback, а один из ВАРИАНТОВ на шаге 1.
- [ ] Где живёт решение: детерминированно в коде (if/else, cache-first — дёшево, предсказуемо, тестируемо) VS делегировать LLM (гибко, но +токены/+латентность/−предсказуемость). Правило: LLM — только решения, требующие суждения; простой роутинг — в коде.
- [ ] Graceful degradation (лестница fallback при лимите/сбое):
      1) кэш (точный) → 2) ИИ (сам генерит / через tool) → 3) похожий кэш → 4) рецептный API (Spoonacular/Edamam — реальные рецепты) → 5) Google-скрапинг ТОЛЬКО как последний костыль (хрупкий) → 6) грубый локальный матч без ИИ → 7) честное сообщение с retry-after («подождите ~N минут», а не «всё зависло»).
- [ ] Обработка rate-limit: читать retry-after/reset, честно показывать сколько ждать.
